# 商业策略：时间差打法

> 记录日期：2026-11-13。目标定位：零花钱量级，不押重注。

## 窗口期判断

窗口是真实的：semcode 年轻、ArkTS 支持无人做、鸿蒙语义搜索空白、DevEco
用户基数高速增长。**按 6-12 个月规划，目标两个月内出 MVP 上架。**

### 三个威胁（按危险程度排序）

1. **华为自家 AI 助手（最大威胁）**：DevEco 已主打 AI 辅助编程
   （CodeGenie/DevEco Code）。华为有全量 ArkTS 语法树与索引，把语义检索
   喂进自家 AI 比我们容易。这个不取决于我们，窗口可能就一年左右
2. **上游自己加 ArkTS**：semcode 维护活跃。闭源 fork 合法，但上游一旦
   加了 ArkTS，独家性归零，只剩先发装机量与口碑
3. **别人抄同样的作业**：门槛不高（ArkTS 3-5 天 + 插件 3-6 周已被摸清）

## 合规（已确认无坑）

| 组件 | 协议 | 闭源商用 |
|------|------|------|
| semcode | MIT OR Apache-2.0 | ✅ 允许 |
| ONNX Runtime | MIT | ✅ |
| CodeBERT 模型 | MIT | ✅ |
| LanceDB | Apache-2.0 | ✅ |

- 全宽松协议，无 copyleft 污染；义务仅保留版权/许可声明（二进制发行带
  LICENSE/NOTICE）
- **策略：闭源 fork，别急着回馈上游**——回馈等于免费替潜在竞品做 ArkTS
  支持。代价是定期合并上游（上游迭代快）。赚完时间差再回馈换声誉

## 逆向风险评估

分层看，结论：**护城河不建立在代码保密上**。

| 层 | 风险 | 应对 |
|----|------|------|
| Kotlin 插件层 | JVM 字节码，FernFlower/CFR 分分钟还原近源码，**视同公开** | 逻辑上不放敏感东西；license 校验不放这层 |
| Rust 二进制层 | Ghidra/IDA 可出伪 C，还原可维护源码需数周 | release + `strip=true` + `panic="abort"` |
| 模型权重 | CodeBERT 本来就公开下载 | 无 |
| 通信协议 | LSP/JSON-RPC 可抓包 | 无敏感内容 |

若商业化：授权校验走服务端 API，插件层只透传。Marketplace 付费插件机制
可被绕过，行业惯例，拦君子不拦小人。

## 定价与渠道

- **定价低、一次性买断、别做订阅**。个人开发者工具国内付费意愿低；
  JetBrains 付费插件主流价位 $5-15
- 预期管理：200 份 × ¥50 ≈ ¥1 万是合理量级；50 份也不丢人
- 平台抽成低（个位数百分比），但国内用户 JetBrains 支付有摩擦；若转化卡在
  支付，加国内授权码渠道（微信/支付宝 + 简单 license 校验）
- **可考虑 freemium**：基础语义搜索免费冲 Marketplace 排名（排名吃装机量，
  是唯一先发护城河），调用链分析、跨 commit 对比放 Pro

## 维护税警告（上架不是终点）

- DevEco Studio 每次大版本升基线 → 插件兼容范围跟着调
- semcode 上游演进要跟（闭源 fork 的合并成本）
- 用户 issue 要回
- **MVP 砍到最小**：语义搜索 Tool Window + 一键索引 + ArkTS/C++，导航类
  锦上添花先不做（打不过原生）

## 隐性回报

鸿蒙工具链生态里「第一个做 ArkTS 语义搜索的人」，简历与圈层价值可能超过
插件本身收入。
