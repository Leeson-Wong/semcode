## 二、Java 语言支持（下午，端到端完成）

评估文档 dev/01-java-support.md（含全部接缝清单）。要点：

- **grammar**：官方 `tree-sitter-java 0.23.5`（crates.io 最新），与核心
  tree-sitter 0.26 ABI 兼容，编译零问题
- **两个查询编译坑**（记录避免再踩）：
  1. Java 基本类型（void/int/boolean…）是**未命名 token**，`(_)` 匹配
     不了，type 捕获必须枚举 `(void_type)` 等 8 种命名节点
  2. tree-sitter 0.26 查询规划器要求字段顺序贴近语法产生式——`type:`
     必须写在 `name:`/`parameters:` **之前**，否则报 Impossible pattern
- **qualifier 设计**：package 从 AST 的 `package_declaration` 读（不信
  文件路径——jdk17 的 `src/java.base/share/classes/` 布局路径≠包名），
  嵌套类全链保留：`java.util.Objects::requireNonNull`
- **注解**占 macro 位但不落库（与 Python 装饰器同待遇，零 @Override 噪声）
- **构造器**：name 节点同时挂 `@function_name @return_type` 两个捕获
- **调用边**：所有 `method_invocation` 记名字级边（含 `obj.foo()`——
  Java 调用图可用的关键）；`this.x()` 用 `#eq?` 谓词匹配成带 owner 边；
  `new Foo()` 记为构造器调用边
- **参数**：`formal_parameter` 走字段；`spread_parameter`（`String...`）
  无字段定义，按子节点位置读，类型渲染为 `String...`（原样）

**实测结果（jdk17）**：594,670 函数（原 212,697，Java 增约 38 万）；
find_function `indexOf` 110 定义带完整 qualifier 和 Javadoc；find_type
`CharSequence` 正确识别 interface；vgrep 能搜 Java 函数体；find_callers
`requireNonNull` 消歧横幅列 4 个 owner。向量步骤完成。

**插件**：extensions 串加 `java`，版本 **0.2.0 → 0.3.0**，
zip 在 `plugin/build/distributions/semcode-intellij-0.3.0.zip`，
**需要用户重装**。MCP 端 index_project/启动自动索引用
`supported_extensions()`，零改动自动含 java。
